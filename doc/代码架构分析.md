**总体架构**
- 多项目单库，包含三个核心子项目：amphi-etl、amphi-scheduler、jupyterlab-amphi；统一以 Hatch+hatch-jupyter-builder 构建 Python 包，Yarn/Lerna 管理并构建 JupyterLab 前端扩展<mccoremem id="03fikkyre9fsrnh4w3wsomsmc" />。
- 运行形态为“JupyterLab+扩展”的桌面/浏览器应用：Python 端提供 CLI、服务器扩展与配置；前端 TS/React 扩展实现主题与可视化数据管道组件。

**子项目与职责**
- amphi-etl
  - 角色：发行包与总入口，整合主题/组件的前端扩展和 Lab/Server 配置并分发。
  - 关键文件：构建与共享数据映射见 [pyproject.toml](file:///d:/mycode/amphi-etl/amphi-etl/pyproject.toml#L47-L55)；CLI 入口在 [main.py](file:///d:/mycode/amphi-etl/amphi-etl/amphi/main.py)；历史构建脚本见 [setup.py](file:///d:/mycode/amphi-etl/amphi-etl/setup.py#L24-L49)。
  - 前端扩展：主题 [theme-light](file:///d:/mycode/amphi-etl/amphi-etl/packages/theme-light/package.json)，UI 组件 [ui-component](file:///d:/mycode/amphi-etl/amphi-etl/packages/ui-component/package.json)。
  - 配置分发：Lab 配置与设置、服务器配置映射到标准 Jupyter 目录，见 [pyproject.toml:shared-data](file:///d:/mycode/amphi-etl/amphi-etl/pyproject.toml#L49-L54) 与示例配置 [page_config.json](file:///d:/mycode/amphi-etl/amphi-etl/config/labconfig/page_config.json)、[overrides.json](file:///d:/mycode/amphi-etl/amphi-etl/config/settings/overrides.json)、[pipeline_scheduler.json](file:///d:/mycode/amphi-etl/amphi-etl/config/server-config/pipeline_scheduler.json)。

- amphi-scheduler
  - 角色：管道调度的服务器扩展（Python）与对应前端 Lab 扩展。
  - 服务器扩展：路由/加载在 [handler.py](file:///d:/mycode/amphi-etl/amphi-scheduler/packages/pipeline-scheduler/pipeline_scheduler/handler.py)，包含扩展注册与 API 处理器。
  - 前端扩展：包定义与脚本在 [pipeline-scheduler/package.json](file:///d:/mycode/amphi-etl/amphi-scheduler/packages/pipeline-scheduler/package.json)，含开发辅助命令如 watch Lab 扩展（如你打开的脚本行）。
  - 构建分发：通过其 [pyproject.toml](file:///d:/mycode/amphi-etl/amphi-scheduler/pyproject.toml) 将静态产物与服务器配置复制到 Jupyter 标准目录。

- jupyterlab-amphi
  - 角色：ETL 可视化组件库（TS/React），分为核心组件与本地组件两套包。
  - 核心组件包 [pipeline-components-core](file:///d:/mycode/amphi-etl/jupyterlab-amphi/packages/pipeline-components-core/package.json)，本地组件包 [pipeline-components-local](file:///d:/mycode/amphi-etl/jupyterlab-amphi/packages/pipeline-components-local)。
  - 组件涵盖多源输入、转换、联接、聚合、输出等，见各 TSX 文件目录结构。

**构建与分发**
- Python 构建
  - Hatch/hatchling 作为构建后端，版本来源统一在 _version.py，见 [amphi-etl/pyproject.toml](file:///d:/mycode/amphi-etl/amphi-etl/pyproject.toml#L5-L13)。
  - hatch-jupyter-builder 负责调用 jlpm 构建前端，并将产物以 shared-data 映射到 Jupyter 的 labextensions、labconfig、lab/settings、jupyter_server_config.d 等位置，确保安装后 Jupyter 自动发现扩展。
- 前端构建
  - Yarn/Lerna 管理工作区与多包；各包通过 package.json 的 jupyterlab 字段声明扩展元信息与输出目录，最终由 Python 构建阶段打包进 wheel。

**运行与交互**
- CLI 启动
  - console_scripts 注册 amphi 命令指向 [amphi.main:main](file:///d:/mycode/amphi-etl/amphi-etl/setup.py#L44-L48)，用于启动 JupyterLab 并加载扩展与配置。
- 服务器扩展加载
  - Jupyter 启动时加载 amphi-scheduler 的服务器扩展，注册 REST 路由，提供调度任务查询、创建、执行等服务。
- 前后端联动
  - UI 扩展在 JupyterLab 中渲染；通过 discovery/共享数据机制与服务器扩展联通，使用 REST API 实现调度与管道运行。

**当前 setup.py 的定位**
- amphi-etl 的 [setup.py](file:///d:/mycode/amphi-etl/amphi-etl/setup.py#L1-L49)为历史/备用入口，声明依赖、入口与 data_files，但与现行 pyproject 的 Hatch 流程存在重叠与不一致（例如将整个 amphi 目录复制到 labextensions）。现代安装将优先使用 pyproject 的 PEP 517/518 构建；建议以 pyproject 为主。
