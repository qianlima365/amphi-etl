# ETL 本体管理功能规划文档

## 1. 背景与目标

### 1.1 背景

- 当前 ETL 流水线生成依赖规则匹配与有限模板，大模型对「组件类型、配置、组件间关系」缺乏**结构化知识**。
- 希望引入**本体论（Ontology）**：用图结构显式建模组件、配置、关系，使大模型可基于精准本体数据理解用户需求并生成合规 ETL 工作流。

### 1.2 目标

- **本体资源统一管理**：组件类型、组件配置、组件间关系等以图数据形式存储（如 Neo4j），便于查询与推理。
- **管理员维护入口**：提供管理页面，支持对手动维护组件、配置、关系进行增删改查。
- **可视化与检索**：提供图/列表可视化与搜索，方便查看对象类型关系及全库数据。
- **与现有 AI 流水线打通**：本体数据可供 ai-service 的意图识别、GraphBuilder、Validator 等使用，用于生成与校验 ETL 工作流。

## 2. 核心概念（本体模型）

### 2.1 对象类型（节点类型）

| 概念         | 说明                     | 示例                         |
|--------------|--------------------------|------------------------------|
| **Component  | 组件类型**               | 对应前端 BaseCoreComponent   |
| **Parameter  | 参数/配置项**            | 组件表单字段                 |
| **DataType   | 数据类型**               | pandas_df、documents、table  |
| **Category   | 分类/目录**              | inputs、transforms、outputs  |

### 2.2 关系类型（边类型）

| 关系                     | 说明                           | 示例                          |
|--------------------------|--------------------------------|-------------------------------|
| **HAS_PARAMETER**        | 组件拥有参数                   | MySQLInput → host             |
| **ACCEPTS_INPUT**        | 组件接受的输入数据类型         | Filter → pandas_df            |
| **PRODUCES_OUTPUT**      | 组件输出的数据类型             | CsvFileInput → pandas_df      |
| **CAN_FOLLOW**           | 可连接顺序（下游可接上游）     | CsvFileInput → Filter         |
| **BELONGS_TO_CATEGORY**  | 组件属于某分类                 | MySQLInput → inputs.Databases  |
| **PARAMETER_TYPE**       | 参数值类型/约束                | host → string                 |
| **OPTION_OF**            | 枚举选项属于某参数             | "table" → queryMethod         |

### 2.3 与现有组件元数据对应

- **Component**：对应 `components-metadata.md` 中的 `componentName`、`id`、`description`。
- **Parameter**：对应每个组件的 `parameters` 数组项（name、type、default、required、options、description）。
- **DataType**：对应组件在 Pipeline 中的 `type`（如 `pandas_df_input`、`pandas_df_processor`、`documents_processor` 等），可归一为抽象类型如 `pandas_df`、`documents`。

## 3. 功能模块规划

### 3.1 本体数据管理（管理端）

**角色**：管理员。

| 功能 ID | 功能名称           | 描述 |
|---------|--------------------|------|
| F-OM-1  | 组件类型管理       | 增删改查 Component 节点；支持从现有 components-metadata 或接口同步/导入。 |
| F-OM-2  | 组件配置/参数管理  | 对每个组件维护其 Parameter 及 HAS_PARAMETER；支持参数类型、默认值、必填、options（枚举）等。 |
| F-OM-3  | 关系管理           | 维护 ACCEPTS_INPUT、PRODUCES_OUTPUT、CAN_FOLLOW、BELONGS_TO_CATEGORY 等关系；支持批量与单条编辑。 |
| F-OM-4  | 数据类型与分类管理 | 维护 DataType、Category 节点，并与 Component 通过关系关联。 |
| F-OM-5  | 导入/导出          | 支持从现有 YAML/MD/JSON 导入本体；支持导出为 JSON/CSV 供他系统使用。 |

### 3.2 本体可视化与搜索

| 功能 ID | 功能名称       | 描述 |
|---------|----------------|------|
| F-VS-1  | 图可视化        | 以图形式展示节点（Component/Parameter/DataType/Category）与关系，支持缩放、拖拽、高亮邻居。 |
| F-VS-2  | 列表/表格视图   | 按类型筛选查看组件/参数/关系列表，支持分页与排序。 |
| F-VS-3  | 搜索            | 按名称、ID、描述、类型、分类全文或条件搜索；结果可跳转图视图定位。 |
| F-VS-4  | 关系路径查询    | 查询两节点间路径（如「从某 Input 组件到某 Output 组件的合法连接链」），结果可高亮在图视图中。 |

### 3.3 与 AI 服务集成

| 功能 ID | 功能名称           | 描述 |
|---------|--------------------|------|
| F-AI-1  | 本体查询 API       | 为 ai-service 提供接口：按需求关键词查组件、按输入/输出类型查可连接组件、拉取参数 Schema。 |
| F-AI-2  | 生成时引用本体     | GraphBuilder/生成逻辑从图库读取 CAN_FOLLOW、ACCEPTS_INPUT、PRODUCES_OUTPUT 等，生成合规边与节点。 |
| F-AI-3  | 校验时引用本体     | Validator 校验节点类型、参数、连接关系是否与本体一致。 |

### 3.4 系统与权限（可选）

| 功能 ID | 功能名称     | 描述 |
|---------|--------------|------|
| F-SYS-1 | 访问控制     | 管理端可要求登录；仅管理员可写，只读用户仅可视化与搜索。 |
| F-SYS-2 | 操作审计     | 关键写操作（创建/更新/删除组件或关系）记日志，便于追溯。 |

## 4. 用户故事（摘要）

- **管理员**：在「本体管理」页新增一个组件，为其添加参数与「可连接」关系，保存后在图视图中看到新节点与边。
- **管理员**：从现有 components-metadata 一键导入为图数据，再在图中修正部分关系或补充描述。
- **开发者/运维**：在图视图中搜索「MySQL」，查看所有与 MySQL 相关的组件及上下游关系。
- **AI 服务**：用户说「从 MySQL 读到 Excel」，后端通过图库查询「输出 pandas_df 的 MySQL 输入组件」和「接受 pandas_df 的 Excel 输出组件」，生成合规 Pipeline。

---

## 5. 非功能需求

- **性能**：图库查询（单跳/多跳）响应时间目标 &lt; 500ms（万级节点内）。
- **可用性**：管理端与可视化界面需支持现代浏览器；图数据库需支持备份与恢复。
- **可维护性**：本体模型与关系类型可配置扩展，不硬编码在前后端。

---

## 6. 与现有系统边界

- **数据源**：组件定义仍以代码（BaseCoreComponent + components-metadata）为权威来源；本体图库为「派生与增强」数据，可定期从元数据同步或手动维护。
- **调用方**：ai-service 的 agent/generate、validate、templates、nodes 等可读图库；写操作仅通过管理端或独立导入任务进行。
