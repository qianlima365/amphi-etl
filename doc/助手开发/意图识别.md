重构意图识别服务，使用大模型语义理解替代关键字匹配作为主要方式。

更新 `chatHandler.ts`，将用户的模型配置传递给意图识别服务：


## 新架构：基于 LLM 语义理解

### 核心流程

```
用户输入
    ↓
Step 1: 快速过滤（输入 ≤5 字符 → none）
    ↓
Step 2: LLM 语义理解（主要方式）
    ↓ 失败时
Step 3: 规则匹配（降级方案）
    ↓
返回意图结果
```

### LLM 意图分类提示词

```
你是一个精准的意图分类器。你的任务是分析用户输入，判断用户的真实意图。

## 判断规则
1. 保守原则：如果不确定，优先判断为 none
2. 明确性原则：只有当用户明确表达了数据处理需求时，才判断为 pipeline_generate
3. 上下文原则：简短的输入（如"好的"、"继续"）通常是 none
4. 语义理解：理解用户的真实意图，而不是简单的关键词匹配

## 输出格式
{
  "intent": "pipeline_generate" | "pipeline_edit" | "none",
  "confidence": 0.0-1.0,
  "reason": "简短说明判断理由"
}
```

### 调用参数

现在 `IntentService.recognizeIntent` 接受模型配置：

```typescript
const intentResult = await IntentService.recognizeIntent(messages, { 
  threshold: 0.6,
  userId,
  providerId: modelConfig?.providerId,  // 启用 LLM
  model: modelConfig?.model,
  apiKey: modelConfig?.apiKey,
  baseUrl: modelConfig?.baseUrl
});
```

### 优势

| 特性 | 之前（关键词匹配） | 之后（LLM 语义理解） |
|------|------------------|---------------------|
| "你好" | 可能误判 | `none` (问候语) |
| "你是谁" | 可能误判 | `none` (询问身份) |
| "ETL 是什么意思" | 可能误判为生成 | `none` (概念询问) |
| "帮我把数据从 A 导到 B" | 需要精确关键词 | `pipeline_generate` (语义理解) |
| "弄个处理用户数据的流程" | 无法识别 | `pipeline_generate` (语义理解) |

### 降级保障

当 LLM 不可用时（未配置模型、调用超时、解析失败），自动降级到规则匹配，确保服务可用性。
